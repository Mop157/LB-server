# Игровой Master Server

Серверная часть игрового проекта. Приложение написано на TypeScript, использует Node.js, Express и MongoDB. Оно предоставляет HTTP API для регистрации и проверки аккаунтов, сохранений, списка игроков онлайн, чата, подарков, промокодов и игровых событий.

## Требования

- Node.js версии 20 или новее.
- npm.
- Доступный сервер MongoDB.

Для локальной разработки MongoDB можно запустить на этом же компьютере. Для рабочего развёртывания используйте отдельную базу и отдельного пользователя MongoDB с минимально необходимыми правами.

## Установка и запуск

Все команды выполняются из корневой папки проекта.

Установите зависимости и создайте локальный файл конфигурации:

```powershell
npm ci
Copy-Item .env.example .env
```

Откройте `.env` и при необходимости укажите параметры подключения к MongoDB и сетевые настройки.

### Запуск в режиме разработки

```powershell
npm run dev
```

В этом режиме сервер запускается непосредственно из TypeScript через `ts-node`.

### Сборка и запуск

```powershell
npm run build
npm start
```

Команда сборки компилирует TypeScript в JavaScript и записывает результат в `dist/`. `npm start` запускает собранный сервер. Папки `dist/` и `node_modules/` не нужно добавлять в Git: они исключены через `.gitignore`.

### Проверка типов

```powershell
npm run typecheck
```

Проверка типов не запускает сервер и не создаёт выходные файлы.

## Переменные окружения

При запуске сервер автоматически загружает переменные из файла `.env`. Не публикуйте этот файл и не добавляйте в исходный код пароли, токены или закрытые адреса подключения.

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `MONGO_URI` | `mongodb://127.0.0.1:27017/mygame` | Строка подключения MongoDB. В конце указывается имя базы данных. |
| `HOST` | `0.0.0.0` | Сетевой интерфейс, на котором сервер принимает подключения. |
| `PORT` | `16261` | Порт HTTP-сервера. Допустимый диапазон: от 1 до 65535. |
| `DISCOVERY_PORT` | `16262` | UDP-порт для автоматического поиска сервера в локальной сети. |

Пример локального `.env`:

```dotenv
MONGO_URI=mongodb://127.0.0.1:27017/mygame
HOST=0.0.0.0
PORT=16261
DISCOVERY_PORT=16262
```

Если MongoDB требует имя пользователя и пароль, используйте выданную провайдером строку подключения и храните её только в `.env` или в системе управления секретами. Не вставляйте секретную строку в README, коммиты, скриншоты или сообщения об ошибках.

`0.0.0.0` означает прослушивание всех сетевых интерфейсов. Это может сделать сервер доступным извне, если порт открыт в брандмауэре или на хостинге. Для локального тестирования можно использовать `127.0.0.1`.

### Фоновая работа и поиск сервера

Сервер работает в одном процессе: HTTP API, периодическая очистка и UDP-обнаружение не требуют Node.js cluster. Каждые две минуты сервер удаляет устаревшие записи игроков онлайн, а раз в час ограничивает историю публичного чата.

Для работы поиска:

- телефон и компьютер с сервером должны быть подключены к одной локальной сети;
- на компьютере должны быть разрешены входящие подключения к TCP-порту `PORT` и UDP-порту `DISCOVERY_PORT`;
- в Android-проекте Corona/Solar2D в `build.settings` должно быть разрешение `android.permission.INTERNET`:

```lua
settings =
{
    android =
    {
        usesPermissions =
        {
            "android.permission.INTERNET",
        },
    },
}
```

Некоторые роутеры и гостевые Wi-Fi-сети блокируют обмен пакетами между устройствами. В такой сети автоматический поиск работать не будет. UDP broadcast предназначен только для локальной сети и не обеспечивает поиск сервера через интернет.

Для диагностики после запуска клиента проверьте вывод Solar2D/Android: сообщение `UDP-запрос поиска сервера отправлен...` означает только, что клиент передал пакет своей сетевой подсистеме. В консоли сервера должны появиться сообщения `LAN discovery request received...` и `LAN discovery reply sent...`. Если сервер не пишет о полученном запросе, проверьте разрешение Android, подключение телефона к той же Wi-Fi сети, изоляцию клиентов на точке доступа и правило брандмауэра Windows для входящего UDP-порта `16262` (или значения `DISCOVERY_PORT`). Если запрос на сервере виден, но клиент не печатает `Получен UDP-ответ поиска...`, сеть или Android блокирует обратный UDP-пакет.

В Windows можно добавить входящие правила для локальной сети из PowerShell, запущенного от имени администратора:

```powershell
New-NetFirewallRule -DisplayName "Game server discovery UDP 16262" -Direction Inbound -Protocol UDP -LocalPort 16262 -RemoteAddress LocalSubnet -Action Allow -Profile Any
New-NetFirewallRule -DisplayName "Game server API TCP 16261" -Direction Inbound -Protocol TCP -LocalPort 16261 -RemoteAddress LocalSubnet -Action Allow -Profile Any
```

Если в `.env` заданы другие значения `DISCOVERY_PORT` или `PORT`, замените номера портов в командах на свои.

```text

  database/          Схемы и модели MongoDB

  setting/           Игровые параметры, права и тексты команд
  logger.ts          Запись событий и действий пользователей в MongoDB
  server.ts          Точка входа, запуск HTTP- и фоновых процессов

  saves.ts           Одноразовая утилита миграции данных сохранений
  logs.py            Необязательная диагностическая утилита на Python
static/
  enemy/             Изображения игровых противников
```

## API

Все игровые маршруты начинаются с `/api`. Для защищённых маршрутов клиент должен передавать в теле запроса `login`, `code` (токен аккаунта) и `version` (версию клиента). Регистрация и получение времени имеют отдельные параметры. Конкретный формат ответов зависит от обработчика и существующего игрового клиента.

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/time.json` | Получить время сервера и параметры ограничений. |
| `POST` | `/api/register_account.json` | Создать аккаунт; передаются версия клиента и идентификатор устройства `token`. |
| `POST` | `/api/restore_account.json` | Проверить или восстановить аккаунт; дополнительно требуется `tokenI`. |
| `POST` | `/api/newname` | Установить или изменить имя игрока. |
| `POST` | `/api/dead` | Очистить подарки игрока после смерти персонажа. |
| `POST` | `/api/saves/try_load.json` | Загрузить сохранение игрока. |
| `POST` | `/api/saves/try_save.json` | Сохранить профиль игрока. |
| `POST` | `/api/try_use_promocode.json` | Использовать промокод. |
| `POST` | `/api/try_load_players.json` | Получить список игроков онлайн. |
| `POST` | `/api/chat/load_message.json` | Загрузить сообщения чата. |
| `POST` | `/api/chat/save_message.json` | Отправить сообщение в чат. |
| `POST` | `/api/try_send_gift.json` | Отправить подарок. |
| `POST` | `/api/load_gift.json` | Получить список подарков игрока. |
| `POST` | `/api/take_gift.json` | Забрать подарок. |
| `GET` | `/api/enemies2/:filename` | Получить PNG-изображение из `static/enemy/`. |

Проверка актуальной версии клиента задана в `src/setting/setting.ts`. Формат запросов и ответов нужно сверять с кодом обработчиков и клиентом, использующим этот сервер.

## Хранение данных

Основное рабочее хранилище — MongoDB. Модели и схемы коллекций описаны в `src/database/database.ts`, а модели журналов — в `src/logger.ts`. Сервер хранит аккаунты, сохранения, состояние игроков онлайн, сообщения чатов, подарки, баны, журналы и настройки событий.

Локальные JSON-выгрузки из `src/database/data/` удалены, поскольку содержали данные пользователей и не использовались активным сервером на MongoDB. Эта папка исключена из публикации в Git. Не загружайте в репозиторий реальные базы, дампы, токены, пользовательские данные или журналы.

Статические изображения находятся в `static/enemy/`. Перед публикацией или распространением проверьте, что у вас есть права на все изображения и другие включённые в проект материалы.

## Служебные скрипты

Эти файлы не запускаются командой `npm start`:

- `src/main.ts` — диагностический скрипт для проверки записей пользователей и идентификаторов клиента в MongoDB. Использует `MONGO_URI`; необязательная переменная `DB_NAME` задаёт имя базы, по умолчанию `mygame`.
- `src/saves.ts` — одноразовая миграция, которая переносит поля профилей пользователей в коллекцию сохранений и удаляет их из документов пользователей. Перед запуском обязательно сделайте резервную копию базы и сначала проверьте скрипт на копии данных.
- `src/logs.py` — диагностический скрипт на Python. Для него отдельно требуется установить пакет `pymongo`. Настройки подключения можно передать через `MONGO_URI`, `DB_NAME`, `LOGS_COLLECTION` и `OUTPUT_FILE`.

Не запускайте миграционные и диагностические утилиты на рабочей базе, если не понимаете их последствия и не имеете проверенной резервной копии.
